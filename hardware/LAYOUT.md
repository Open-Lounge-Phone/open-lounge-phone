## 1. How to run

```sh
cd hardware
make build     # schematic: ERC, checks, netlists, BOMs, cost roll-up (one board, one BOM)
make layout    # footprints -> place + route (cached) -> key plate -> checks -> fab outputs
make all       # both
make layout FORCE=1   # re-place and re-route even if the inputs did not change
```

`make layout` uses KiCad's bundled Python (`KICAD_APP` overrides the location; the default is
`~/Applications/KiCad/KiCad.app` or `/Applications/KiCad/KiCad.app`) and installs PyYAML and
numpy into `hardware/.tools/pylib` (git-ignored). No network access is needed after that.
`make freerouting` fetches FreeRouting 2.4.1 + a Java 25 runtime for the optional
`build_board.py --router freerouting` path. It is not the default: on these boards FreeRouting
plateaued at 50-120 unrouted connections.

| Step | Script | Output |
|---|---|---|
| Custom footprints + 3D models | `layout/footprints/gen_footprints.py` | `layout/footprints/openloungephone.pretty`, `.3dshapes` |
| Logo (owner signature) | `art/make_logo.py` (run with `.venv/bin/python`) | `openloungephone_logo_F/B.kicad_mod`, `art/logo-preview.png` |
| Place | `layout/build_board.py <board> --stage place` | `kicad/<board>/<board>.kicad_pcb` (+ `.kicad_pro`, `.kicad_dru`, `fp-lib-table`) |
| Route + pours + stitching | `layout/build_board.py <board> --stage route` | same file, `kicad/<board>/unrouted.txt` |
| Key plate | `layout/build_board.py plate` | `kicad/plate/plate.kicad_pcb` |
| Checks | `layout/checks.py <board>` | `build/<board>/layout/checks.txt`, `drc.json`, `drc.rpt` |
| Fab outputs | `layout/export.py <board>` | `build/<board>/layout/` (below) |
| Everything, cached | `layout/run_layout.py` | all of the above |

Routing takes minutes, so `run_layout.py` re-places and re-routes a board only when the SHA-256
of its inputs (netlist refs/footprints/nets, `boards.yaml`, `placement.yaml`, footprints, layout
scripts, rule file) changes; otherwise it only syncs the footprint fields (values, DNP, LCSC)
from the netlist. The hash is in `kicad/<board>/inputs.sha256`. Outputs are deterministic:
fixed UUIDs (uuid5 of reference/position), no timestamps in Gerbers, sorted zip members.

**What a human edits:** `layout/placement.yaml` (positions of ICs, connectors and anything
position-critical, plus the two hand-routed USB traces), `layout/boards.yaml` (outlines, holes,
keep-outs, zones, net classes, key grid, silkscreen texts). Resistors, capacitors, beads and test
pads are placed automatically next to the pin they serve (`auto_place` in `build_board.py`:
nearest legal spot on growing rings around the anchor pad; the decoupling-cap notes in the
schematic pick the anchor IC). The KiCad files under `hardware/kicad/` are generated; hand edits
there are overwritten on the next run.

## 3. Stackup and impedance

Generic 1.6 mm 4-layer, 7628 prepreg (JLC04161H-7628 / PCBWay standard), ENIG:

| Layer | Use |
|---|---|---|
| L1 F.Cu 35 µm | parts, signals, GND fill | e-ink boost, sensors, GND fill, signals |
| prepreg 0.21 mm εr 4.4 | | |
| L2 In1.Cu | **solid GND** (no routing) | **solid GND** |
| core 1.065 mm | | |
| L3 In2.Cu | 3V3 and VSYS pours + slow signals, GND fill | slow signals + GND fill |
| prepreg 0.21 mm | | |
| L4 B.Cu 35 µm | signals, test pads, GND fill | sockets, LEDs, expander, NFC, ZIFs, GND fill |

USB D+/D− (both pairs): 0.27 mm tracks, 0.15 mm gap on L1 over the L2 plane. With 0.21 mm to the
plane and εr 4.4 this is ≈ 90 Ω differential by the IPC-2141 edge-coupled estimate (JLC's
calculator gives 88-92 Ω for this stackup; verify with the fab's calculator before ordering if
you change fab). Full-speed USB (12 Mb/s) is tolerant of ±15 %, so this is not critical.

## 4. Design rules and net classes

Rules = the intersection of common 4-layer capability (JLCPCB, PCBWay, OSH Park, Eurocircuits,
Aisler, Seeed, NextPCB), in `layout/fab-common.kicad_dru` (copied as `<board>.kicad_dru`):
track/clearance ≥ 0.15 mm, drill ≥ 0.3 mm, via 0.6/0.3 mm (annular 0.15), copper to edge
≥ 0.3 mm, hole to hole ≥ 0.5 mm, silk text ≥ 0.8 mm.

| Class | Nets | Track / clearance | GUIDELINES §5 |
|---|---|---|---|
| Default | everything else | 0.2 / 0.15 | as specified |
| Bus | I2C, I2S, EPD SPI, LED data, IRQ, UART | 0.2 / 0.2 | as specified |
| USB | USB_DP/DN (CH340C), HS_USB_DP/DN (handset, native USB) | 0.27 / 0.15, pair gap 0.15 | as specified |
| Audio | mic inputs, DAC out, AEC reference, PA input, MICBIAS | **0.2 / 0.2** | **deviation**: guideline says 0.25 / 0.3. The ES7210/ES8311 have 0.4 mm-pitch QFN pins; 0.25/0.3 cannot leave them. Analog runs are short and sit between the L1/L4 GND fills over the L2 plane; a 0.5 mm audio-to-speaker clearance rule is in the rule file. |
| Power3V | 3V3, 3V0 | 0.4 / 0.2 | as specified |
| Power | VBUS, VSYS, VBAT, VLED, SCAP, HS_VBUS, HS_VIN | 0.6 / 0.25 | as specified; neck-down only in ≤ 1 mm stubs at fine-pitch pins (checked) |
| Speaker | NS4150B outputs | 0.5 / 0.25 | as specified |
| GND | GND | pours + 0.4 mm fan-out | as specified |

Net classes are assigned by `netclass_rules` in `boards.yaml` (regex on net names plus pad-based
rules for auto-named nets) and written into the board and the `.kicad_pro`.

## 6. Board structure and routing plan (step B)

**Planes, not wires.** L2 = solid GND. L3 = pours: 3V3 (middle band), VSYS (right end), 3V0
(codec cluster), VLED (two strips under the key rows). Every pin on those nets gets a via to its
plane next to the pad (via-in-pad or ≤ 1 mm stub); no power wires are drawn. Real wide traces
only where current flows: VBUS (J1 → F1 → BQ24074, radar switch, handset diode), VSYS neck to
the pour, speaker outputs (0.5 mm).
L1 = short links and fan-out, mostly left-right; L4 = mostly front-back (key lines, LED hops).

**Blocks are local clusters with their own decoupling.** Only these signals leave a block, each
in a planned channel:

| Inter-block signal | From → to | Channel |
|---|---|---|
| Handset USB pair | J7/D7 → U1 | L1 in `HS_USB_CORRIDOR`, no vias |
| I2S (5) | U1 bottom-left pins → codecs below | L1, straight down, 15-31 mm |
| I2C spine (+ IRQ alongside) | U1 → codecs → LIS2DH12 → ALS → AW9523B → MAX17048; one long branch to the ST25DV at the NFC coil | L1/L3 short daisy chain round the codec cluster; the ST25DV branch on L3 along the front band |
| EPD SPI bundle (6) | U1 left pins → J6 | L1 parallel bundle, leftward, < 20 mm |
| LED data | U1 → U5 → MENU LED → … → status | L4 serpentine along the rows |
| Key buses (2 × 6) + VOL/MUTE (3) | sockets → AW9523B at the right end | L4: rear row lanes y 23.2-25.5 then down beside/under the ESP32 into U17's left side; front row lanes y 63.1-65.4 into its bottom side; side controls straight in from the right edge |
| Mic pair + MICBIAS | ES7210 ↔ mic ↔ MUTE switch | short L1 links at the right end (≤ 39 mm), away from I2S |
| UART, EN/BOOT, CC sense, charger status | right-end parts ↔ U1 right-side pins | L1 short links |

Routing is done in sequential blocks; each ends with a numeric check before the next starts:

| Block | Scope | Numeric check |
|---|---|---|
| A. Power and PDN | pours on L3, via-to-plane at every plane pin, VBUS/VSYS/speaker traces | every plane pin has a via ≤ 1 mm; power widths ≥ class minimum; DRC 0 errors |
| B. ESP32 + both USB-C ports | handset pair, J1 → CH340C pair, CC, UART, EN/BOOT | handset pair ≤ 25 mm, 0 vias, mismatch ≤ 0.15 mm; DRC 0 errors |
| C. I2C / SPI / I2S | spine, EPD bundle, I2S | I2S within 10 mm of each other; 0 I2S/SPI segments within 1 mm of Audio tracks on the same layer; DRC 0 errors |
| D. Analog audio | mic pair, AEC divider, DAC → amp, speaker, MICBIAS | Audio 0.2/0.2 mm; 0 vias on BASEMIC_P/N inside the cluster; speaker ≥ 0.5 mm; DRC 0 errors |
| E. Keys and LED chain | key bus, LED data hops, VLED vias — **uniform scripted traces (pcbnew), not autorouted** | 0 unconnected items; all 13 LED hops identical; DRC 0 errors |

## 6b. Router notes (first layout, e3eda11; the hand route below is superseded by §6 B)

- **Hand routes** (`placement.yaml` → `routes`): the handset USB pair HS_USB_DP/DN from the
  SRV05-4 at J7 to ESP32 GPIO19/20, on L1 only, no vias, over the solid L2 plane: out of D7,
  up between J7 and hole H1, along the rear edge above the key bodies, down between key
  columns 3 and 4, along y 23 to the module's left pads; 161.3 mm each (a bump on D−
  matches them). Full-speed USB (12 Mb/s) does not care about the length; the match keeps
  the pair coupled.
- **Escape stubs** leave every fine-pitch (< 0.8 mm) pad in its own direction at pad width;
  **GND fan-out** puts a GND via at every SMD GND pad (in-pad for exposed pads).
- **Grid router** (`layout/router.py`, deterministic): 0.1 mm grid, three routing layers
  (L1, L3, L4; L2 stays solid GND), A* with via cost and layer preference, net order by class
  (power first, then USB, audio, bus, default), rip-up and reroute when a connection is blocked
  by earlier routes, class widths and clearances, neck-down only inside pads' escape area,
  keep-outs and board edge respected. GND is not routed: it connects through the pours and
  fan-out vias. Unrouted connections, if any, are listed in `kicad/<board>/unrouted.txt`.
- **Pours:** GND fill on all four layers (L2 solid), 3V3 and VSYS on L3 (main), stitching vias
  every 5 mm and along the edges; none inside the antenna or NFC keep-outs.
